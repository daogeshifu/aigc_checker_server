# Demo 任务日志

`/demo` 与 `/test` 底部分为「本次任务日志」和「全部任务日志」。

## 本次任务日志

每次检测或改写独立折叠，执行中每两秒读取真实服务端步骤，本页保留最近 20 次。仅展示核心信息：

- 任务 ID、接口、来源、字符数与请求状态。
- 开始时间、返回时间、总耗时；每个步骤展示发生时间及累计耗时。
- 接收请求、清洗分块、检测路由、结果聚合、条件复核、改写及返回结果。分块步骤同时展示分块数、并发块数和并发上限；默认按块数动态并发，最多 10 路。
- 模型实际调用的成功、尝试、失败和待确认次数，以及失败/回退步骤。
- 检测标签、风险分与置信度；改写前后风险分、是否保留改写和质量分。

日志不重复展示逐块统计特征、分块评分表、浏览器请求记录或完整 JSON。当前请求的完整接口响应仍可在上方「分析结果 → 查看原始 JSON 返回」查看。

“已返回”表示接口已完成，不保证全部模型调用成功。模型回退和证据不足会在结果摘要中提示。

## 全部任务日志

自动读取服务端已保存的任务，包括 Demo、接口测试页以及直接调用 `/api/scan`、`/api/reduce` 创建的任务。可查看成功、进行中和执行失败的记录，页面刷新后仍可查询。

- 通过来源、类型、状态、Task ID 筛选，服务端每页返回 20 条并展示筛选后的总数。
- 列表显示结果、开始时间、返回时间与总耗时。
- 点击「查看过程」查看任务核心执行步骤，包含失败与回退。
- 默认每五秒刷新列表和打开的任务详情，可关闭自动刷新或手动刷新。即使当前列表没有执行中任务，也能发现新的外部 API 任务。
- `API_TOKEN` 为管理 Token，可查看全部调用方；`FREE_API_TOKENS`、`PRO_API_TOKENS` 只能查看各自的任务。切换或清除 Token 时立即清空历史列表和详情，旧请求不能覆盖新 Token 的结果。

服务端默认保留最近 200 个任务，由 `TASK_LOG_MAX_RECORDS` 配置。配置大于 200 时，可通过分页查看全部保留记录。列表会显示当前保留上限。鉴权或参数校验未通过的请求不会创建检测任务；已有日志会说明请求未进入引擎。

服务端只保存脱敏步骤和结果摘要，不保存访问 Token、请求原文、提示词或改写内容。新任务摘要同时保存证据状态和检测警告，刷新后也能看到回退/证据不足提示。

## 接口字段与兼容

`GET /api/tasks` 保留原 `items` 字段，新增：

- `limit`、`offset` 分页参数，每次最多 200 条。
- `source=demo|test|api`、`task_type=scan|reduce`、`status=running|success|failed`、`search`（任务 ID 子串）筛选。
- 响应 `total`（筛选后的任务数）、`can_view_all_tasks`、`retention_limit`。

任务摘要和详情新增 `returned_at`：服务端完成任务并准备返回结果/错误的时间，执行中为 `null`。旧记录可从已有完成时间读取，无需迁移数据库。单次日志结束后还展示浏览器接收到响应的时间；所有时间按浏览器所在时区显示。

检测和改写可传唯一 `request_id`（UUID）。页面据此构造 `scan-<UUID去掉连字符>` 或 `reduce-<UUID去掉连字符>`，无需等待同步 POST 返回即可查询对应任务。重复标识返回 HTTP 409，且不会覆盖原任务。原客户端可不传此参数，检测/改写响应结构不变。

引擎异常的 HTTP 500 / 502 响应包含 `X-Task-ID`，便于查询失败轨迹。所有查询继续校验 Token 权限。

## 更新部署

需同步 Python 和 `web/` 前端源码后，在服务器项目目录重建 API 容器：

```bash
sudo bash manage.sh update api
```

原 `.env` 和 `data/` 沿用现有配置及数据。更新后刷新 `/demo`，填写管理 Token，检查「全部任务日志」，并从第三方 API 发起一次检测，确认记录出现且可查看过程。

本地验证使用模拟模型与独立临时数据库，覆盖实时任务关联、正常返回、失败回退、错误返回时间、超过 200 条的分页、筛选和调用方隔离；浏览器检查筛选、详情、完成结果、刷新后读取与 Token 切换。
