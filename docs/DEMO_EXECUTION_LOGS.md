# Demo 执行日志

`/demo` 与 `/test` 底部展示本页最近 20 次检测或改写请求。每次请求独立折叠，执行中每两秒读取一次真实服务端记录；也可手动刷新日志。

可查看：

- 请求时间、HTTP 状态、Task ID、累计耗时及请求规模。
- Ollama、Azure、OpenRouter 的实际调用尝试、成功、失败与待确认次数。
- 清洗、分块、逐块模型判断、统计评分、文体校正、文档聚合、远端复核及改写步骤。
- 失败回退、证据不足、PPL / NLL 是否启用及是否取得测量值。
- 逐块评分、完整接口 JSON、服务端事件 JSON 和浏览器请求记录。

“接口成功”只表示请求正常返回。若发生模型失败回退、复核失败或证据不足，记录会标为“已返回 · 需要关注”，并展示具体步骤。开始事件标为“开始 / 发起”，不代表该调用已经成功；失败回退分块的模型分显示“未使用”。

页面不展示访问 Token，也不在请求日志中保存 Token 或请求原文。完整接口输出可能包含本次输入对应的文本分块，仅保留在当前页面内存。页面刷新后，可在现有 `/tasks` 页面查询服务端保存的脱敏步骤与结果摘要；服务端默认保留最近 200 个任务，由 `TASK_LOG_MAX_RECORDS` 配置。

## 请求关联与兼容

检测和改写请求新增可选 `request_id`（UUID）。页面用它构造本次任务 ID（`scan-<UUID去掉连字符>` 或 `reduce-<UUID去掉连字符>`），因此无需等待 POST 返回即可查询确切任务。所有任务详情查询沿用原有 Token 权限校验。重复使用请求标识返回 HTTP 409，且不会覆盖已有任务。

原有客户端可以不传 `request_id`，原响应结构不变。引擎异常的 HTTP 500 / 502 响应新增 `X-Task-ID` 头，便于继续查询失败任务。鉴权或参数校验未通过时不会创建任务，页面会明确说明未进入引擎。

## 更新部署

本次同时修改 Python 和前端代码，需同步整个更新包后重建检测 API 容器，不能只复制 HTML：

```bash
cd /home/html/aigc_checker_server
sudo env SKIP_GIT_PULL=1 bash disploy.sh
```

原 `.env` 和 `data` 目录沿用现有配置及数据。更新后刷新页面，通过一次检测检查底部日志。已有 Ollama 容器继续使用。

本地验证使用模拟模型响应与独立临时数据库，覆盖真实 HTTP 请求、执行中查询、正常返回、部分模型失败回退、引擎异常、Token 无效及不同调用方权限隔离；不代表已验证生产模型的检测准确率。
